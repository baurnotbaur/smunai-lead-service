# Сервис заявок для отдела продаж

Мини-CRM: сайт отправляет заявки → менеджеры разбирают их в панели.
Нужен Node.js 24+. База — SQLite: локально это файл, в облаке — Turso (та же SQLite по сети),
переключается одной переменной окружения.

## Запуск

```bash
cd lead-service
npm install
cp .env.example .env   # на Windows: copy .env.example .env
npm start
```

Панель: <http://localhost:4000>. Первый вход — `admin@local` / `admin12345` (значения из `.env`,
поменяйте пароль в разделе «Сотрудники» сразу после первого входа).

`npm run reset` — стереть базу и начать с нуля.

## WhatsApp и Instagram

Оба канала принадлежат Meta и приходят на один адрес:

```
<PUBLIC_URL>/api/v1/webhook/meta
```

Написал человек в WhatsApp или в директ — заводится заявка, она попадает в общий список
рядом с заявками с сайта. Следующие сообщения того же человека дописываются в ту же карточку,
пока разговор не закрыт стадией «Успех» или «Отказ». Переписка видна в карточке, оттуда же
менеджер отвечает.

Комментарии под постами в Instagram приходят на тот же вебхук и тоже становятся заявками:
бот отвечает под комментарием публично, а разговор дальше ведётся в карточке.

## Бот

Задайте `ANTHROPIC_API_KEY` — и на сообщения отвечает Claude. Без ключа бот остаётся
сценарным: здоровается, просит телефон, зовёт менеджера.

**Бот отвечает только по базе знаний.** Её текст правится в панели, раздел «Бот», и целиком
попадает в системный промпт. Чего в ней нет — про то бот честно говорит «уточню у менеджера»
и передаёт разговор человеку: `bot_off` у заявки становится `1`, в истории появляется отметка,
и дальше бот в этот диалог не вмешивается. Так же он поступает, когда клиент торгуется,
жалуется или просит особые условия.

Это ограничение намеренное. Выдуманная цена или адрес в переписке — это обещание, которое
потом расхлёбывает отдел продаж, поэтому пустая база знаний означает не «бот сам разберётся»,
а «бот всё переводит на менеджера». Заполните её до того, как подключите каналы.

Менеджер, ответивший из карточки, тоже выключает бота в этом диалоге — чтобы клиенту
не отвечали двое сразу.

Отказ модели ничего не ломает: заявка уже сохранена, в лог уходит причина, а клиент получает
сценарный ответ. Выключить автоответ целиком — `BOT_ENABLED=0`.

Что нужно со стороны Meta:

1. Бизнес-аккаунт Meta и приложение на developers.facebook.com.
2. Для WhatsApp — номер, не занятый в обычном WhatsApp, и постоянный токен
   (создаётся через системного пользователя, временный живёт сутки).
3. Для Instagram — профессиональный аккаунт, привязанный к странице Facebook,
   и включённый доступ к сообщениям в настройках Instagram.
4. Проверка бизнеса и App Review — без них каналы работают только на тестовых номерах
   и аккаунтах разработчиков.
5. В настройках вебхука указать адрес выше и ту же строку, что в `META_VERIFY_TOKEN`,
   подписаться на события `messages`.

Подпись каждого запроса проверяется секретом приложения. Пока `META_APP_SECRET` не задан,
вебхук отклоняет всё — адрес публичный, и без проверки любой мог бы слать выдуманные заявки.

**Про ответы клиенту.** WhatsApp разрешает свободно писать только 24 часа с последнего
сообщения клиента; позже — лишь заранее утверждённые шаблоны, и они платные. У Instagram
окно семь суток. Если ответ не уходит, причина обычно в этом — текст ошибки от Meta
показывается в панели как есть.

## Если не войти в панель

Пароль хранится хешем и восстановлению не подлежит, но его можно переписать прямо в базе.
Учётка администратора заводится только при пустой базе, поэтому менять `ADMIN_PASSWORD`
в этом случае бесполезно — нужен скрипт:

```bash
npm run passwd                              # какие учётки есть
npm run passwd -- почта новый-пароль        # задать пароль
```

Если такой почты в базе нет, скрипт заведёт её с ролью администратора. Все открытые сессии
этого пользователя закрываются, чтобы вошедший ранее не остался внутри.

Скрипт работает с той базой, что настроена в окружении. Чтобы поправить **боевую** базу
в Turso, передайте её адрес и токен прямо в команде — переменные окружения важнее `.env`:

```bash
TURSO_DATABASE_URL=libsql://ваша-база.turso.io TURSO_AUTH_TOKEN=... npm run passwd
```

В PowerShell то же самое пишется иначе:

```powershell
$env:TURSO_DATABASE_URL="libsql://ваша-база.turso.io"; $env:TURSO_AUTH_TOKEN="..."; npm run passwd
```

Первая строка вывода всегда показывает, с какой базой скрипт работает, — сверьтесь с ней,
прежде чем менять пароль.

## Как подключить сайт

Раздел **«Подключение сайта»** в панели показывает ключ и готовый код. Два варианта:

**1. Виджет — ничего не программировать.** Вставьте перед `</body>`:

```html
<script src="http://localhost:4000/embed.js?key=ВАШ_КЛЮЧ" defer></script>
```

и пометьте форму атрибутом `data-lead-form`:

```html
<form data-lead-form>
  <input name="name"  placeholder="Имя">
  <input name="phone" placeholder="Телефон" required>
  <input name="_hp" style="display:none" tabindex="-1" autocomplete="off">
  <button type="submit">Отправить заявку</button>
</form>
```

Виджет перехватит отправку, добавит UTM-метки, referrer и адрес страницы,
а на форме вызовет события `lead:success` / `lead:error` — на них можно повесить свою «спасибку».
Скрытое поле `_hp` — ловушка для ботов.

**2. Свой код.** POST на `/api/v1/leads`:

```bash
curl -X POST http://localhost:4000/api/v1/leads \
  -H "Content-Type: application/json" \
  -d '{"key":"ВАШ_КЛЮЧ","name":"Иван","phone":"+7 700 000 00 00","comment":"Текст заявки"}'
```

Ответ: `{"ok":true,"id":12,"message":"Заявка принята"}` либо `{"ok":false,"error":"...","message":"..."}`.
Обязателен телефон **или** email. Любые лишние поля формы сохраняются в карточке заявки.

Сайт «С Мунай» из соседней папки уже подключён — настройки в `index.html`, блок `window.LEADS_CONFIG`.

## Что умеет

- **Приём заявок**: ключ на сайт, ограничение по доменам, honeypot, лимит запросов с одного IP,
  пометка дублей (тот же телефон в течение 30 минут), сбор UTM / referrer / страницы.
- **Работа с заявкой**: стадия воронки, ответственный, сумма сделки, причина отказа, комментарии
  и полная история изменений.
- **Своя воронка**: этапы настраиваются под ваш процесс (Новая → Квалификация → КП → Договор),
  можно менять порядок, цвет и тип. Тип `won`/`lost` говорит аналитике, что считать успехом и
  отказом. Удалить непустую стадию можно только с переносом заявок — они не теряются.
- **Распределение**: автоназначение на наименее загруженного активного менеджера.
- **Контроль скорости**: SLA первого контакта (по умолчанию 15 минут), просроченные заявки видны
  в списке, на доске и в аналитике.
- **Живые обновления**: новые заявки и правки коллег появляются в панели сами, без перезагрузки
  страницы (Server-Sent Events, поток `/api/events`).
- **Компании и контакты**: заявка сама привязывается к организации (по названию или БИН) и к
  контактному лицу (по телефону). «ТОО «Такси Плюс»» и «такси плюс» считаются одной компанией.
  В карточке компании — реквизиты, все контактные лица и вся история заявок.
- **Дела и напоминания**: «перезвонить», «отправить КП» со сроком и ответственным. Раздел «Дела»
  делит их на просроченные / сегодня / дальше, в меню горит счётчик. Дела заводятся прямо из
  карточки заявки и попадают в её историю.
- **Доска** с перетаскиванием карточек между статусами.
- **Аналитика**: заявки за сутки/неделю/месяц, среднее время реакции, конверсия, сумма выигранных,
  разрез по источникам и по менеджерам.
- **Маркетинг**: сегменты клиентской базы (стадия, давность заявки, менеджер) и выгрузка
  рекламных аудиторий для Instagram (Meta) и TikTok. Телефоны и почты хешируются SHA-256 по
  спецификации площадок — сырые контакты наружу не уходят. В выгрузку попадают только те, кто
  дал согласие на рекламу и не отписался.
- **Согласие на рекламу**: приходит галочкой с формы сайта (поле `consent`) или ставится вручную
  в карточке компании; хранится с датой и источником — это доказательство законности рассылки.
- **Выгрузка CSV** с учётом текущих фильтров (открывается в Excel, разделитель `;`, UTF-8 BOM).
- **Уведомления**: Telegram (токен и chat_id в `.env`) и вебхук на новую заявку (настраивается у сайта).
- **Роли**: администратор (сайты, сотрудники, удаление заявок) и менеджер.

## Настройки (.env)

| Переменная | Зачем |
|---|---|
| `PORT` | порт сервиса |
| `PUBLIC_URL` | внешний адрес — попадает в ссылки уведомлений |
| `SESSION_SECRET` | секрет сессий, обязательно свой на проде |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | первая учётка, создаётся только при пустой базе |
| `DB_PATH` | путь к файлу базы (когда не задан Turso) |
| `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` | сетевая база — для облака, где нет своего диска |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления о новых заявках |
| `SECURE_COOKIES` | `1`, когда сервис работает по HTTPS |

## Вывод в интернет

Сервис слушает обычный HTTP — ставьте его за nginx/Caddy с сертификатом и проксируйте на `PORT`.
После этого:

1. `PUBLIC_URL=https://ваш-домен`, `SECURE_COOKIES=1` в `.env`;
2. в карточке сайта укажите разрешённые домены — тогда чужой сайт не сможет слать заявки с вашим ключом;
3. смените пароль администратора;
4. настройте автозапуск (systemd на Linux, `nssm`/Планировщик задач на Windows);
5. базу `data/leads.db` включите в резервное копирование.

## Деплой на Vercel

В настройках проекта задайте **Root Directory = `lead-service`** — иначе задеплоится содержимое
корня репозитория, а не сервис. Версия Node берётся из `engines` (24.x).

Дальше всё описано в `vercel.json`, и каждая строка там появилась не просто так:

- `outputDirectory: panel` — статикой раздаётся только папка панели. Без этого Vercel публикует
  весь каталог сервиса, и `server.js` с `src/*.js` можно скачать с домена;
- функция собирается из `api/index.js` — обычный `server.js` в корне платформа как точку входа
  не подхватывает;
- `rewrites` заворачивают `/api/*` в функцию, а остальные пути — на `index.html`, чтобы работали
  внутренние ссылки панели.

Папка панели называется `panel/`, а не `public/`, тоже намеренно: имя `public` Vercel считает
готовой статикой и публикует её как обычный сайт.

### База для облака

У функции нет своего диска, поэтому файловая база там не живёт: без `TURSO_DATABASE_URL`
она создаётся в `/tmp` и пропадает при холодном старте вместе с заявками, паролем
администратора и ключом сайта.

Заведите базу на [turso.tech](https://turso.tech), возьмите в разделе **Connect** адрес и токен
и добавьте в переменные окружения проекта:

```
TURSO_DATABASE_URL=libsql://ваша-база.turso.io
TURSO_AUTH_TOKEN=...
```

Схема создастся сама при первом запуске. Диалект SQL тот же, что у локального файла, — код
запросов для обоих случаев общий, различается только строка подключения в `src/db.js`.

Проверить, что получилось, можно без ключа и без входа в панель:

```bash
curl https://ваш-домен/api/v1/health
```

`{"db":"turso","persistent":true}` — база сетевая и заявки не пропадут;
`{"db":"file","persistent":false}` — сервис работает на временном файле в `/tmp`.

## Структура

```
server.js              локальный запуск: поднимает HTTP-сервер
api/index.js           точка входа для Vercel: та же обработка, но без своего сервера
src/app.js             разбор запроса и маршрутизация — общее для обоих запусков
src/config.js          чтение .env
src/db.js              подключение (файл или Turso), схема и первичное наполнение
src/auth.js            пароли (scrypt), сессии в куках
src/leads.js           приём заявки, автораспределение, смена статусов
src/notify.js          Telegram и вебхуки
src/routes/public.js   публичный приём заявок (CORS, лимиты, honeypot)
src/routes/meta.js     вебхук WhatsApp и Instagram
src/channels/meta.js   подпись, разбор и отправка сообщений через Graph API
src/conversations.js   диалог: узнавание собеседника, история, передача менеджеру
src/ai.js              ответы Claude строго по базе знаний
src/settings.js        настройки из панели, включая базу знаний
src/routes/api.js      API панели
panel/                 панель (index.html, app.js, style.css) и embed.js
```
